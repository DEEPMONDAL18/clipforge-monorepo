# ENG-010 — Shared Types Migration

## Engineering Ticket

ID: ENG-010

Title: Shared Types

Priority: Critical

Sprint: 2D

Status: Planned

---

# OBJECTIVE

Establish the canonical shared TypeScript type definitions required by
the ClipForge frontend and future service/API layers.

ENG-010 consolidates reusable domain and application types into the
approved shared-type location without implementing backend services,
API integration, authentication, or business logic.

The objective is to create a stable type contract that future tickets
can depend upon.

# TYPE MIGRATION RULES

When an existing type already exists:

1. Inspect it.
2. Determine whether it is reusable.
3. If appropriate, move/consolidate it into the canonical shared type
   location.
4. Update only the imports required to use the canonical type.
5. Preserve the existing type semantics.

Do NOT create duplicate versions of an existing type.

Do NOT silently alter the meaning of an existing type.

If two types conflict:

STOP and document the conflict rather than arbitrarily choosing
one definition.
